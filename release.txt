## What's Changed

**Fixes the recurring Passthrough drops and slow dashboard updates that appeared in v1.18.9/v1.18.10.**

- fix: HardwareWatchdog now judges control-loop liveness by **setpoint writes** instead of telemetry reads. It no longer forces the inverter into passthrough (Optimized mode + 0W) when the loop is slow-but-alive; the failsafe only fires after both setpoint writes and D-Bus telemetry have been silent for the full 30s timeout. Dry-run never triggers.
- perf: control loop no longer dumps the full D-Bus tree every cycle (`get_battery_soc_local` reuses the sys_data already fetched by the loop) and reuses the MPPT/Tasmota reads from `calculate_setpoint` in `update_state` (~8 fewer D-Bus calls/cycle). This restores fast ~1s cycles and fresh dashboard updates.
- perf: `get_ess_mode` is cached for 5s (invalidated on write); battery/charger cache TTL raised to 10s to smooth periodic bursts.
- test: new `tests/test_watchdog.py` — active loop never fails over, stalled loop forces 0W safe mode, recovery restores external control + setpoint, dry-run never triggers.

Full test suite: 234 passing.
